Relational broker pipeline progress

The entries below are chronological; the latest section records the folder split, standalone calculation, and presentation headers.

8 September 2026 — implementation and refinement

Implemented the final Broker2 model through the typed relation machinery in Cubical/Experiments/Relation. The development has ten pipeline modules and a qualified entry point, imported by the Broker2, Theory, and full financial umbrellas. The abstract V01–V07 sources remain unchanged.

The source boundary supplies finite keyed trade, collateral and receipt catalogs, client references, and rational valuation snapshots. Operations preserve trade and client IDs and return a dense client result and call table. Financial inputs remain symbolic; no numerical scenario or external service is required.

Reusable relation machinery now includes get, finite key masks, tabulation, projection, selection, weighted sums and grouping. The getter derives its result type and membership requirement from the schema. Proofs cover projection and selection folds, finite indexed sums, append, and receipt-key replay/reordering. Relation/Base.agda was preserved byte for byte.

Implementation separated from properties

Following the requested separation, the runnable data code is in ValuationImplementation, ReceiptImplementation, and Implementation. These modules import no abstract broker engine or financial correctness module. They use get directly in relational expressions; the custom owner/amount getters and redundant mask alias were removed. process accepts ordinary rational report data and returns ordinary state, remaining amounts, call rows, and a status tag.

Valuation and Receipts prove accounting refinement. FiniteRisk supplies the rational-to-real sum and maximum bridges and a computed conservative revaluation reserve. Correctness certifies the actual data implementation; it does not contain another process implementation. A valid initial report is computed exactly, and a report remains valid after partial receipts.

The final Refinement theorem pipeline-correct proves:

  • the returned state and its computed, state-indexed report match V07's process;
  • returned remaining amounts and call rows match the model;
  • the actual status tag carries the stated evidence: fulfilled calls and the risk bound, or an identified client whose quote is unmet;
  • sufficient newly credited cash bounds every client residual by its MTA and broker residual/every admissible severity-weighted loss by total MTA, for independent indexed source sums in every supplied stress.

Zero MTA gives full modeled coverage and zero modeled loss. Stability lifts replay and two-batch reordering to the concrete state and its dependent risk certificate at a fixed valuation. Unchanged valuation computes zero reserve and recovers V06's quote. The report equality in Refinement compares the particular computed reports, not arbitrary upper bounds.

Review and scope

Independent agents implemented generic relation/finite-risk operations and the receipt-accounting proof, separated valuation, and reviewed the full chain. The final review found no accounting or refinement defect. It specifically checked that current cash is included once, new cash is subtracted once, replayed IDs add nothing, the maximum fold's trailing zero is justified, and certificates refer to the actual program output.

The guide records the assumptions: authorized netting sets, complete and correctly keyed catalogs, disjoint eligible collateral inventory, immutable/authentic available receipts at par in the common account currency, and suitable supplied valuations. External strings and snapshot numbers are metadata, not authenticated or checked identifiers. A conservative unfulfilled quote does not prove economic deficiency. Fixed catalogs and supplied stresses do not model all lifecycle events or future markets.

No postulate, hole, unsafe pragma, weakened option or missing analysis axiom was introduced. There is no claim about pricing calibration, external database execution, floating-point arithmetic, persistence or throughput. References and a five-minute extension to the seven-version presentation are linked in the guide.
